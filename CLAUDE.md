# CLAUDE.md — Real-Time Anomaly Detection & Self-Remediating Agent Platform

You (Claude Code) are the implementer. The human is the architect and reviewer.
Full spec lives in `docs/PROJECT_PLAN.md`. This file is your operating manual —
follow it on every task.

## What we're building
A production-shaped real-time streaming platform that detects anomalies under provable
correctness guarantees, explains them, and auto-remediates via a safety-gated agent.

## How we work (non-negotiable)
- Build in **working increments**. Every task ends with something that runs end-to-end
  and is reviewed before the next one starts. Never scaffold broad, empty structure.
- **Depth over breadth.** No stubs that pretend to work. If a thing isn't built yet, it
  is absent — not faked.
- **The human must be able to defend every choice in an interview.** For each non-trivial
  decision, append a short entry to `docs/DECISIONS.md` (what, why, alternatives rejected).
  Anything with a real tradeoff: stop and ask the human to decide — do not choose silently.
- **Honest claims.** Scope correctness claims to exactly where they hold (see the
  exactly-once boundary in the plan). Never overstate.
- **Measure, and report losses.** When the foundation-model detector goes in, benchmark it
  against the z-score baseline and report where it loses, not only where it wins.

## Code standards (this project must not read as autogenerated)
- No emoji anywhere — code, docs, or commit messages.
- Comment the *why*, not the *what*. No line-by-line narration.
- Domain-specific names. No `FooManager`, no `utils`/`helpers` dumping grounds.
- Small, reviewable commits with real messages (the reason, not "update files").
- README leads with results and how to run it — no marketing prose.
- Secrets via `.env` only; compose and entrypoints fail loudly if a var is unset. Never
  hardcode a credential.
- Tests for every component before moving on.

## Stack (detail in the plan)
Kafka + Flink (exactly-once) · ClickHouse / Iceberg / Postgres · zero-shot time-series
foundation-model detector + VLM explainer (flagged windows only) · MCP + vLLM +
safety-gated agent · Ragas / DeepEval / TruLens · Docker / Kubernetes / Terraform /
GitHub Actions · Prometheus / Grafana · React + FastAPI. Python 3.12.

## Build order (current phase marked)
0. Requirements & design — DONE (this file + the plan).
1. **← CURRENT. Thin spine:** loadgen → Kafka → consumer → windowing → z-score baseline
   detector → detected episodes in Postgres. Then add the foundation-model detector.
2. Correctness backbone: Flink, event-time + watermarks, exactly-once (2PC), reconciliation
   harness, chaos suite, and the throughput/scale harness.
3. Serving & storage: ClickHouse + Iceberg.
4. Explainability + agent: VLM on flagged windows, MCP tools, Diagnoser → Planner →
   Safety Gate → Executor on a sandbox, runbook RAG, model on vLLM.
5. Tuned agent + eval: QLoRA fine-tune of the tool-calling model, Ragas / DeepEval / TruLens.
6. Production wrapper: harden K8s/Terraform/CI, polish README + <60s demo.

## Definition of done (every increment)
Runs end-to-end from documented commands · tests pass · config and secrets externalised ·
a `docs/DECISIONS.md` entry per real choice · the human has reviewed it and can explain it.

## Do not
- Build more than the current phase. Do this one, stop, wait for review.
- Add monitoring before there are metrics worth scraping.
- Write raw readings to Postgres — Postgres holds detected *episodes*; serving data goes to
  ClickHouse (Phase 3); the durable lake is Iceberg.
- Fake numbers or bury poor results.
